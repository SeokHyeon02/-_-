# MyLink PRD (기능 정의서)

## 목표
사용자가 프로필 이름, 소개글, 외부 링크를 한 페이지에 모아 실제 URL로 공유하는 서비스. 과제 배점은 GitHub 내 MyLink 폴더(9점)와 Vercel 배포 후 실제 URL(1점) 두 항목을 우선 충족한다.

## 사용자
- **방문자:** 로그인 없이 공개 마이링크의 프로필/링크 조회 및 외부 링크 이동
- **소유자:** Google 로그인, 프로필 변경, 링크 생성/수정/삭제, 개인 URL 공유

## 요구 기능

| ID | 기능 | 우선순위 | 수락 기준 |
|---|---|---|---|
| F-01 | GitHub 폴더 | 필수 | 저장소 내부에 `MyLink/`와 소스파일이 존재 |
| F-02 | 실제 접속 URL | 필수 | Vercel 배포 URL 접속 시 홈페이지 렌더링 |
| F-03 | 공개 프로필 | 권장 | 이름, 소개글, 링크 목록 표시 |
| F-04 | 링크 CRUD | 추가 | 입력 유효성 검증, 인라인 수정, 확인 후 삭제 |
| F-05 | Google Auth | 추가 | 사용자별 로그인, 로그아웃, 상태 감지 |
| F-06 | 사용자별 데이터 분리 | 추가 | `users/{uid}/...` 경로에 저장 |
| F-07 | 동적 개인별 페이지 | 추가 | `/[username]` 공개 조회 및 없는 경우 오류 표시 |
| F-08 | Firestore 권한 | 추가 | 누구나 읽기, 본인만 쓰기 |
| F-09 | 반응형 | 품질 | 360px·768px·1024px 화면에서 주요 기능 사용 가능 |

## 핵심 시나리오

1. 소유자가 `/mypage`로 이동해 Google 로그인을 진행한다.
2. username/displayName/bio를 입력하고 저장한다. 중복 username이면 오류를 본다.
3. 제목/URL을 입력해 링크를 추가한다. 잘못된 URL이면 입력 오류를 본다.
4. 링크를 편집/삭제한 뒤 페이지를 새로고침해 결과 유지 여부를 확인한다.
5. 개인 주소를 복사해 다른 브라우저에서 연다. 방문자는 로그인 없이 볼 수 있고 수정은 못 한다.

## 비기능 요구사항
- 악성 `javascript:` 등의 링크 차단, `http/https` 주소 검증
- 사용자 아이디 3~24자, 영문 소문자/숫자/밑줄/하이픈
- Firestore Rule 적용 및 사용자명 점유 트랜잭션
- 반응형 인터페이스, 접근성 라벨, 외부 링크 새 탭 열기와 안전한 rel 속성

## 배포 및 범위
- 소스: GitHub `MyLink/` 하위 폴더
- 웹: Vercel Next.js 프로젝트 Root Directory를 `MyLink`로 설정
- 데이터: Firebase Auth + Cloud Firestore 연결 시 활성화
- 모드: Firebase 미설정 시 로컬 데모 제공(다른 사용자에게 수정 상태 동기화되지 않음)
